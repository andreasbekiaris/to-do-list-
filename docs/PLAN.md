# Product and phase plan

Thread is a single-user nested to-do app used from a Mac, Windows PC, and phone. One Next.js app hosted on Vercel becomes the installable desktop/mobile app via PWA support. No native clients.

Stop after each phase and summarize for review. The owner reported successful production registration and login. Phase 2 task features are deployed. The user then requested desktop installation, appearance customization, Day/Week/Month calendar organization, and drag-and-drop reparenting with the ability to move tasks back out, authorizing those additions ahead of Phase 3. AI writing remains deferred.

## Phase 1 — foundation

- Next.js App Router, strict TypeScript, pnpm, Tailwind and shadcn/ui primitives.
- Neon Postgres with Drizzle and the Neon HTTP driver; first SQL migration.
- Auth.js Credentials with username/password login and a one-time owner account creation flow. This replaces GitHub OAuth at the user's request.
- A protected workspace page, a public login page, Vercel configuration, and agent conventions.
- Acceptance: deploy to Vercel, create the owner account using the private setup code, log in with its username/password, reject incorrect credentials, and prevent creation of a second account.

## Phase 2 — tasks

- Home cards for root tasks: title, description preview, deadline badge, direct child count/progress.
- Detail pages: title, description, optional date/time, nested child list and child creation.
- Arbitrary nesting; recursive SQL CTE for breadcrumbs. Progress uses completed / total direct children.
- Dashboard filters: All / Today / Upcoming / Overdue / Done.
- Optimistic completion with rollback on error. Completing a parent with unfinished descendants asks “Also complete N sub-tasks?”; mutation must apply consistently to the confirmed set.
- Confirm deletion when children exist; use cascade deletion.
- Due badges are red when overdue, amber today. Timed deadlines display in the device timezone. Calendar-only dates must not shift across devices.
- Responsive grid on desktop, one column on mobile, at least 44px tap targets.
- Acceptance: create a three-level tree on desktop and see the persisted tree on a phone.

## Phase 3 — AI writing

- Vercel AI SDK + Anthropic, model `claude-haiku-4-5-20251001`, structured Zod-validated output.
- `suggestTodo({ rawText, parentTitle? })` returns `{ title, description }`, server-side only, authenticated.
- Sparkle button next to every title input; max 500 chars; disable while loading.
- Preview with Accept / Edit / Dismiss. Never overwrite silently; send parent title for children.
- Preserve the input language (Greek or English). Error: “Couldn't generate — try again”.
- Everyday input: “fix the water sink” → “Fix the water sink”, description empty or one short sentence; no invented steps.
- Technical input: “phase 4 making controller api get vessels” → “Phase 4: Build GET Vessels API controller”, 2–4 sentences explaining scope and done criteria.
- `ANTHROPIC_API_KEY` remains only in Vercel's server environment.
- Acceptance: both example inputs and Greek equivalents produce appropriate previews.

## Phase 4 — install and sync

- PWA manifest and icons; Chrome/Edge install, Safari Add to Dock, mobile Add to Home Screen.
- Refresh data on focus/visibility changes. No websockets or offline editing.
- Finish README local setup with `vercel env pull`, deployment, and device installation notes.

## Data model

| Column | Type / behavior |
| --- | --- |
| `id` | UUID primary key, generated by Postgres |
| `parent_id` | Nullable FK to `todos.id`, indexed, `ON DELETE CASCADE` |
| `title` | Nonblank varchar(500) |
| `description` | Text, defaults to empty |
| `is_done` | Boolean, defaults to false |
| `completed_at` | Nullable timestamptz; must agree with completion flag |
| `due_at` | Nullable timestamptz |
| `all_day` | Boolean; true requires a due date |
| `sort_order` | Integer, defaults to zero |
| `created_at` | Timestamptz, defaults to now |
| `updated_at` | Timestamptz, defaults to now; Drizzle updates on mutation |

`owner_accounts` stores the owner UUID, a unique normalized username, a salted password hash, creation time, and a unique/check-constrained singleton flag. `auth_attempts` stores two persistent rate-limit buckets. Auth.js uses encrypted JWT sessions and checks the stored owner UUID on each session read; all private data entry points require that session. No multi-user feature is introduced. For date-only values, UTC midnight encodes a calendar date and display uses UTC date components; timed values are normal instants converted to the device timezone.
